# The Autoresearch Loop

The autoresearch loop is a closed system in which an LLM reads a journal
of past hypotheses and their backtest outcomes, and generates new
hypotheses informed by what has already been tried. It is the
differentiator that no other Indian-market open-source platform
currently offers.

It is also the component most likely to be misused. This document
describes what the loop does, what it does not do, and how to configure
it so that it produces useful research rather than plausible-sounding
noise.

## What the Loop Does

Given a research question and a set of constraints, the loop:

1. Reads the journal of prior hypotheses and their outcomes.
2. Generates one or more new hypotheses, each with a rationale that
   references prior results.
3. Converts each hypothesis into a strategy implementation.
4. Runs the three-tier backtesting pipeline on each.
5. Runs the statistical validation suite on each.
6. Appends the result (success or failure) to the journal.
7. Repeats.

The journal is the memory of the loop. Without it, the LLM produces
the same hypotheses over and over. With it, the loop progressively
narrows toward hypotheses that are both novel and plausible.

## What the Loop Does Not Do

- **It does not produce profitable strategies on demand.** Most
  hypotheses generated by the loop fail validation. This is expected
  and correct — the same is true of human researchers.
- **It does not replace statistical validation.** A generated
  hypothesis that passes backtesting has not been validated. It has
  been shown to be worth validating. The validation suite still runs.
- **It does not search for arbitrary parameter values.** That is a
  job for the parameter sweep in Tier 3, not for an LLM. LLMs are bad
  at numeric optimization and good at structural reasoning.
- **It does not read the news.** Market data is not in the prompt.
  The loop reasons about *ideas*, not about current events. A separate
  tool handles news ingestion.

## The Hypothesis Schema

Every hypothesis is a structured object, not free text:

    from honba.ai.autoresearch import Hypothesis
    from pydantic import BaseModel


    class Hypothesis(BaseModel):
        id: str
        created_at: datetime
        parent_ids: list[str]           # hypotheses this builds on
        statement: str                  # one-sentence claim
        rationale: str                  # why this should work
        universe: str
        timeframe: str
        expected_edge_bps: int          # expected annualized edge
        failure_modes: list[str]        # how this could be wrong
        strategy_code: str              # the actual implementation
        status: str                     # "pending" | "backtested" | "validated" | "rejected"
        result_summary: dict | None

The structured form matters. It forces the LLM to articulate a
falsifiable claim, a rationale, and a set of failure modes before
writing code. Hypotheses without these are rejected by the loop.

## The Journal

The journal is an append-only Parquet file plus a vector index for
retrieval:

    data/journals/
    ├── hypotheses.parquet          # all hypotheses and their results
    ├── embeddings.faiss            # semantic index over hypotheses
    └── research_log.md             # human-readable chronological log

Reading the journal:

    from honba.ai.autoresearch import Journal

    journal = Journal("./data/journals")

    # All hypotheses that touched Alpha30
    journal.search(universe="nifty200_alpha30")

    # Hypotheses similar to a new idea
    journal.similar("mean reversion on midcap bank stocks")

    # Hypotheses that failed, grouped by failure mode
    journal.failures_by_mode()

    # The full tree of descendants of a given hypothesis
    journal.descendants("h_2024_03_17_001")

The retrieval is semantic, not keyword-based, so the LLM sees
hypotheses that are conceptually related even when they use different
vocabulary.

## The Loop API

    from honba.ai.autoresearch import ResearchLoop, LoopConfig
    from honba.ai.llm import LLMProvider

    llm = LLMProvider.claude(model="claude-sonnet-4-5")

    loop = ResearchLoop(
        config=LoopConfig(
            universe="nifty200_alpha30",
            start="2018-01-01",
            end="2024-12-31",
            initial_capital=1_000_000,
            constraints=[
                "Long-only",
                "No leverage",
                "Maximum 20 positions",
                "Daily bars only",
                "Delivery costs",
            ],
            num_trials_budget=100,
            validation_thresholds=ValidationThresholds(
                min_oos_is_ratio=0.5,
                min_deflated_sharpe=0.5,
            ),
        ),
        journal=Journal("./data/journals"),
        llm=llm,
    )

    loop.run(iterations=50)

Each iteration:

1. Prompt the LLM with the research question, constraints, and a
   retrieved set of prior hypotheses (successes and failures).
2. Parse the response into a `Hypothesis`.
3. Validate the hypothesis object (schema, constraints).
4. Run Tier 1 on the generated strategy.
5. If Tier 1 Sharpe > 0.3, run Tier 2.
6. If Tier 2 Sharpe > 0.8, run Tier 3 (Monte Carlo, walk-forward).
7. Run the validation suite.
8. Append the result to the journal.

The loop terminates after `iterations` or when the budget is exhausted.

## Prompt Construction

The prompt has four components:

    ┌───────────────────────────────────────────────────────────┐
    │ SYSTEM                                                    │
    │   Role: quantitative researcher on Indian equities.       │
    │   Constraints: [long-only, delivery, daily bars, ...]     │
    │   Output format: Hypothesis JSON schema                   │
    ├───────────────────────────────────────────────────────────┤
    │ RESEARCH QUESTION                                         │
    │   "Find robust medium-frequency strategies on Alpha30."   │
    ├───────────────────────────────────────────────────────────┤
    │ PRIOR RESULTS (retrieved from journal)                    │
    │   Successes:  [h_001, h_017, h_042]                       │
    │   Failures:   [h_002, h_005, ..., h_099]  (top 20 by sim) │
    │   Failure modes observed: [low trade count, regime-       │
    │     dependent, cost-dominated]                            │
    ├───────────────────────────────────────────────────────────┤
    │ INSTRUCTION                                               │
    │   Generate 1 new hypothesis that:                         │
    │   - Is not a duplicate of any prior hypothesis.           │
    │   - Addresses at least one observed failure mode.         │
    │   - Is falsifiable by backtest.                           │
    └───────────────────────────────────────────────────────────┘

The retrieved prior results are critical. An LLM without them will
generate the same ideas indefinitely. With them, it converges.

## Failure Mode Taxonomy

The loop classifies failures into a fixed taxonomy so that patterns
across many hypotheses are visible:

| Failure mode | Meaning |
|---|---|
| `insufficient_trades` | Fewer than 100 trades in the backtest |
| `cost_dominated` | Gross edge positive, net edge negative |
| `oos_degradation` | OOS Sharpe < 50% of IS Sharpe |
| `regime_dependent` | Positive in some regimes, negative in others |
| `parameter_cliff` | Sharpe collapses with small parameter changes |
| `outlier_driven` | P&L concentrated in a few trades |
| `overlapping_positions` | Position count exceeds constraints |
| `look_ahead_bias` | Uses future information |
| `implementation_error` | Code does not run or produces invalid state |

The LLM is explicitly told which failure modes have been observed and
instructed to address at least one of them.

## Cost Budget

Every loop iteration has three costs:

- **LLM tokens** for prompt and response (~10K tokens per iteration
  with a mid-sized journal).
- **Tier 1 backtest** (~5 seconds per strategy).
- **Tier 2/3 backtests** for survivors (~1 minute each).

For 100 iterations with a 10% Tier 2 pass rate:

    LLM:     100 × 10K tokens ≈ 1M tokens  (~$3 at current pricing)
    Tier 1:  100 × 5s       ≈ 8 minutes
    Tier 2:  10 × 60s       ≈ 10 minutes
    Tier 3:  2 × 300s       ≈ 10 minutes
    ────────────────────────────────────────────
    Total:                    ≈ 30 minutes

This is a realistic overnight run.

## Honest Expectations

The loop is not a strategy generator. It is a **hypothesis filter**.

- Of 100 hypotheses generated, ~60 will fail Tier 1 (obvious
  non-starters).
- Of the remaining 40, ~35 will fail Tier 2 (unrealistic after costs).
- Of the remaining 5, ~4 will fail the validation suite (overfit,
  regime-dependent, or cost-dominated on closer inspection).
- **Roughly 1 in 100 hypotheses survives.**

That survivor is worth paper trading. It is not worth deploying
capital to without further human review and a period of paper trading.

This ratio is not a limitation of the LLM. It is what quantitative
research looks like. Human researchers produce the same ratio; the
loop simply produces it faster.

## When the Loop Fails

Two failure modes are common:

### Repetitive Hypotheses

If the journal retrieval returns the same hypotheses every iteration,
the LLM will generate variations on the same idea. Check that the
embedding index is being updated after each iteration and that the
retrieval query includes recent failures.

### Overly Plausible Nonsense

An LLM can generate a hypothesis that sounds sophisticated but is
based on a misunderstanding of market microstructure. These typically
fail Tier 1 quickly, but if they pass, inspect the code manually
before trusting the result. Common signs:

- Uses `self.last_price()` inside `on_start()`.
- Assumes intrabar fills on daily bars.
- References indicators that do not exist.
- Uses leakage-prone information.

The validation suite catches most of these. Manual review catches the
rest.

## Configuration

    # configs/ai/research_loop.toml
    [loop]
    iterations = 100
    universe = "nifty200_alpha30"
    start = "2018-01-01"
    end = "2024-12-31"
    initial_capital = 1_000_000

    [loop.constraints]
    long_only = true
    max_leverage = 1.0
    max_positions = 20
    timeframe = "1d"
    cost_model = "india_equity_delivery"

    [llm]
    provider = "anthropic"
    model = "claude-sonnet-4-5"
    temperature = 0.7
    max_tokens_per_call = 4096

    [validation]
    min_oos_is_ratio = 0.5
    min_deflated_sharpe = 0.5
    min_trades = 100
    max_top5_contribution = 0.30

    [journal]
    path = "./data/journals"
    retrieval_k = 30
    include_failures = true
